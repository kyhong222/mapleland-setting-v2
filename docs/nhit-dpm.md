# N방컷 · DPM 기획서

피격데미지 섹션과 별개로, **주는 데미지** 기반의 처치 성능을 다룬다.

- **비보스 몹**: 특정 공격스킬로 "정확히 N방에 처치할 확률"을 방컷별로 계산.
- **보스 몹**: HP가 매우 커 N방이 무의미 → 공속 기반 **DPM(분당 데미지)** 계산.

> 상태: 기획 확정 진행 중. `⛳ 필요 데이터` 표시는 사용자(메랜 raw data 검수) 제공 대기.

---

## 1. 목표 · 분기

| 대상 | 판정 | 출력 |
|---|---|---|
| `monster.isBoss !== true` | 비보스 | 방컷별 확률표 (정확히 N방) |
| `monster.isBoss === true` | 보스 | DPM (+ 참고: 처치 소요시간) |

## 2. 한 타(라인) 데미지 분포

### 2.1 기본 물리 데미지 (모션 배수 K 기준)

기존 `attackPower.calcPhysical`와 동일한 식. 무기배수 K를 모션에 따라 바꿔 대입한다.

```
MAX(K) = (주스탯 × K + 부스탯) × 총공격력 / 100
MIN(K) = (주스탯 × K × 0.9 × 숙련도 + 부스탯) × 총공격력 / 100
```

- 한 라인의 **원 데미지 ~ Uniform[MIN(K), MAX(K)]** (min~max 균등분포 가정)
- 마법 스킬은 `calcMagic` 사용(모션 무관, spellAtk 계수 = 스킬 `mad`).

### 2.2 모션 처리 (모션차 있는 무기)

스윙 = `constMax`, 찌르기 = `constMin`. **평균 배수로 뭉개지 않고 모션 확률을 분포에 그대로 반영**한다.

일반 스킬 한 타 = 2성분 혼합분포:

```
한타 = p_찌르기 × Uniform[MIN(constMin), MAX(constMin)]
     + p_베기   × Uniform[MIN(constMax), MAX(constMax)]
```

| 무기 | constMin(찌) / constMax(베) | p_찌르기 : p_베기 |
|---|---|---|
| 한손도끼 | 3.2 / 4.4 | 2 : 3 |
| 한손둔기 | 3.2 / 4.4 | 2 : 3 |
| 두손도끼 | 3.4 / 4.8 | 2 : 3 |
| 두손둔기 | 3.4 / 4.8 | 2 : 3 |
| 창 | 3.0 / 5.0 | 2 : 3 |
| 폴암 | 3.0 / 5.0 | 5 : 5 |

모션차 없는 무기(검·단검·활·완드·스태프 등 `constMin==constMax`)는 단일 균등분포.

### 2.3 스킬별 모션 규칙 (특수 케이스) — skill id 확정 ✅

**기본값 = 일반 2:3 혼합(2.2)**. 대부분 스킬이 평타 모션 기반이라 일반으로 처리하고, 아래 예외만 하드코딩.

| 스킬 | skill id | 라인 | 모션 |
|---|---|---|---|
| 브랜디쉬 | 1121008(히어로)·11111004(소마) | 2 (`attackCount`) | 찌1(constMin)+베1(constMax) |
| 스피어 버스터 | 1311001 | 2 | **2타 모두 찌르기**(constMin=3.0) |
| 폴암 버스터 | 1311002 | 2 | **2타 모두 찌르기**(constMin=3.0) |
| 드래곤 쓰레셔:창 | 1311003 | 1 | 항상 베기(constMax=5.0) |
| 드래곤 쓰레셔:폴암 | 1311004 | 1 | 항상 베기(constMax=5.0) |
| 드래곤 로어 | 1311006 | 1 | 4.0 고정 |
| 파이널 어택(전사 2차) | — | — | **미지원** |
| 그 외 일반 스킬 | — | raw | 일반 2:3 혼합(폴암 5:5) |

### 2.4 시전당 라인 수 — 확정 ✅

- **`attackCount` = 단일 대상에 들어가는 데미지 라인 수** (브랜디쉬·버스터 = 2). 미지정이면 1.
- `bulletCount` = 발사체/표창류 라인 수.
- `mobCount` = 타격 몬스터 수 → **N방컷은 단일 대상만 보므로 무관**(차지블로우 mobCount6도 대상 1마리엔 1라인).

시전 데미지 = 라인 분포들의 **합**. 라인마다 모션이 다르면(브랜디쉬 찌+베) 각각 합성.
단 라인끼리 항상 독립은 아니다 — §2.5.

### 2.5 공격 난수 순환 — 확정 ✅

원작 서버는 공격 1회에 난수를 **7개만** 미리 뽑아두고 판정할 때마다 하나씩 꺼내 쓰다가,
인덱스가 배열을 넘으면 `% 7`로 되돌아가 같은 값을 다시 쓴다.

```c
unsigned int aRandom[7], nRndIdx = 0;
#define PrepareNextRand() nRnd = aRandom[nRndIdx++ % 7]
```

타격 하나가 면역·명중·데미지·방어·크리 5개를 소비하므로 **3타 이상은 7개로 모자라**
재활용이 일어나고, 서로 다른 판정이 같은 난수를 읽는다.
**첫 타만 6개**를 소비한다 — 3타 커플링 1개, 2타 0개, 6타 6개로 실측과 모두 맞는다.
균일하게 5개씩 두면 3타에서 커플링이 2개 나와 실측과 어긋난다.

| 타수 | 데미지 슬롯 | 크리 슬롯 | 커플링 | 대표 스킬 |
|---|---|---|---|---|
| 2 | 2, 1 | 4, 3 | 0 | 브랜디쉬 · 버스터 · 럭키세븐 |
| 3 | 2, 1, 6 | 4, 3, 1 | 1 | 트리플 스로우 · 윈드 샷 |
| 4 | 2, 1, 6, 4 | 4, 3, 1, 6 | 3 | 스트레이프 · 소울 드라이버 |
| 6 | 2, 1, 6, 4, 2, 0 | 4, 3, 1, 6, 4, 2 | 6 | 피스트 · 새비지 블로우 |
| 8 | 2, 1, 6, 4, 2, 0, 5, 3 | 4, 3, 1, 6, 4, 2, 0, 5 | 9 | 데몰리션 |

**성질**: 난수 하나하나는 여전히 균등하고 크리 확률도 그대로다 → **평균·DPM 불변**.
바뀌는 건 라인끼리의 상관뿐이라 시전 총합의 **분산**이 달라지고, 방컷 확률이 움직인다.
데미지↔크리 충돌은 분산을 줄이고(음의 상관), 데미지↔데미지 충돌은 늘린다(양의 상관).
5타 이상은 두 종류가 섞여 방향이 단순하지 않다.

**계산 방법** (`rngCycle.ts` + `skillCombat.assembleCast`):
크리 판정에 쓰이는 슬롯마다 `u < 크리확률`(크리) / `u ≥ 크리확률`(논크리)로 갈래를 나눈다.
갈래를 하나 고정하면 모든 라인의 크리 여부가 정해지고, 남은 자유도는 **데미지 슬롯별로만** 묶이므로
그룹끼리는 다시 독립이다 → 기존 컨볼루션을 그대로 쓴다. 전체 = 갈래별 분포의 가중합.
근사가 아니라 정확 계산이고, 비용은 갈래 수(최대 128)에 비례한다.

> 같은 데미지 슬롯을 읽는 라인들은 **같은 난수** = 완전상관이므로,
> 합이 범위를 더한 단일 균등분포가 된다(모션 조합마다 하나씩).

**시전 간에는 적용하지 않는다.** 난수 배열은 공격마다 새로 뽑히므로
`computeNhit`의 N회 누적과 추가스킬(prior) 합성은 독립이 맞다.

**근거 (실측)**

| 실측 | 대상 | 결과 |
|---|---|---|
| 아카라이브 40회 (2026-08-16) | 트스 3타 | 2줄 데미지 → 3줄 크리, 예외 0건 |
| 스트라이커 피스트 4시전 | 6타 | **5줄 = 1줄 × 2 정확, 크리도 매번 일치 (4/4)** |
| 〃 | 6타 | 데미지↔크리 커플링 5쌍 × 4시전 = **20/20 일치** |

6타의 1줄과 5줄은 `6+5+5+5 = 21`번째 draw에서 시작해 **7의 배수만큼 떨어지므로
다섯 판정이 전부 같은 슬롯**이다. 즉 완전히 같은 롤이고, 피스트는 5타에 ×2 배율이
붙으므로 화면에서 정확히 2배로 뜬다. 이 정렬은 "첫 타만 6개" 가정에서만 나오므로
슬롯 배치의 직접 증거다. (균일 5개면 5줄 데미지 슬롯이 1이 되어 1줄과 겹치지 않는다.)

구현체 4종(mnwvs077·Rebirth95·kinoko·Edelstein)의 배열 크기가 모두 7인 것도 방증.

> **2·3·6타는 실측 확정.** 4·5·7·8타는 같은 규칙에서 유도한 값이라 직접 실측은 없다.
> 다만 규칙 자체가 서로 다른 타수 셋(2·3·6)에서 검증됐으므로 신뢰도는 높다.

## 3. 데미지 파이프라인 (라인 1개 기준)

`computeSkillDamage`(10단계) 재사용. 순서:

1. 기본 데미지 범위 `[min, max]` (2.1, 모션 K 반영)
2. 스킬 퍼뎀(`damage`) / 마법(`mad` 계수)
3. 속성 반응(약점 1.5 / 반감 0.5 / 무효 0)
4. 몬스터 방어 + 렙차 (`physicalVsMonster` / 마법식)
5. **데미지 증가 버프 배율** (4장) 곱
6. **위협 등 몬스터 방어 감소** (5장) 반영
7. **크리 기대배율** `f = 1 + 크리확률 × 크리추뎀/100` (7장)
8. 상한 199999 clamp, floor

결과: 라인 1개의 최종 분포 `~ Uniform[minF, maxF]` (모션 혼합이면 2성분).

### 콤보 어택 공식 (히어로 · 소울마스터) — 확정 ✅

용어(데이터 기준): `combo.damage`, `advCombo.damage`(레벨별), `x` = **최대 콤보 카운터**.
표기상 "퍼뎀" = `data.damage + 100`.

```
maxCounter = 어드밴스드콤보 학습 ? advCombo.x[advLv] : combo.x[comboLv]
카운터 c에서 콤보 뎀증(%):
  c ≤ 5:  combo.damage[comboLv] + (c-1) × (comboLv / 6)
  c ≥ 6:  advCombo.damage[advLv] + 20 + (c-5) × 4
데미지 배율 = 뎀증% / 100
```

- **N방컷/DPM은 최대 카운터 가정**(지속 유지). (원하면 카운터를 UI 입력으로)
- 계산 예:
  - 히어로 30/30 → 10c: 150+20+20 = 190% → **×1.9** / 콤보만 5c: 120+20 = 140% → **×1.4**
  - 소마 20/20 → 10c: 140+20+20 = 180% → **×1.8** / 콤보만 5c: 120+13.3 = 133% → **×1.33**

**패닉 / 코마** (콤보 카운터 전량 소모형): **N방컷·DPM 미제공, 데미지 범위만 표시.**
```
데미지 = 퍼뎀 × 콤보뎀증(위 배율) × 카운터뎀증
카운터뎀증: 1c=×1.0, 2c=×1.2, 3c=×1.54, 4c=×2.0, 5~10c=×2.5
예) 5c 패닉 350% × 1.4 × 2.5 = 1225% (10c: 350×1.9×2.5 = 1662%)
```

### 차지 — 속성반응 대체 (팔라딘 · 소울마스터 · 스트라이커)

차지 사용 시 공격이 **해당 속성**이 됨. §3의 고정 속성반응(약점1.5/반감0.5)을
차지의 데미지배수·속성배수로 **대체**한다. (파이어=플레임, 아이스=블리자드)

> 예전 문서에 있던 레벨 공식(파/아/썬 `1.05+L×0.015`, 홀리 `1.20+L×0.015`)은
> 아래 `z` 표현과 전 레벨에서 동일하다. z 쪽이 원작 코드와 직접 대응하므로 그쪽만 쓴다.

**최종 차지배율** (구현: `domain/paladinCharge.ts`)

원작은 주차지와 보조차지를 각각 계산해 **더한다** — 곱연산이 아니다.
`get_damage_adjusted_by_charged_elemAttr(주) + get_damage_adjusted_by_assist_charged_elemAttr(보조)`

```
차지배율 = 주차지계수 × 속성배수(주) + 보조차지계수 × 속성배수(보조) × 0.5
```

**데미지배수 = `damage`/100** — 차지마다 다르다.

| 차지 | 마스터 `damage` |
|---|---|
| 플레임/파이어 | 140 |
| 블리자드/아이스 | 110 |
| 선더/라이트닝 | 125 |
| 홀리/디바인 | 150 |
| 소울·라이트닝(시그너스) | 120 |

**속성배수 = `z` 기반** — 원작 `get_damage_adjusted_by_elemAttr` 디컴파일과 계수 일치 ✅

원작 코드에 `a3 = z/100`을 대입하면 전 case가 맞아떨어진다.

| elemAttr 자릿수 | 원작 식 | z 표현 | 마스터(z=100) | 시그너스(z=50) |
|---|---|---|---|---|
| 3 약점 | `(a3×0.5 + a4 + 1) × a1` | `1 + z/200` | 1.50 | 1.25 |
| 2 반감 | `(1 − (a3×0.5 + a4)) × a1` | `1 − z/200` | 0.50 | 0.75 |
| 1 무효 | `(1 − a3) × a1` | `1 − z/100` | 0 | **0.50** |
| 없음 | `a1` | 1.0 | 1.0 | 1.0 |

⚠ **무효는 z<100이면 0이 아니다.** 시그너스 차지는 무효 몹에게도 50%가 들어간다.

| 차지 | z 공식 | 마스터 z |
|---|---|---|
| 팔라딘 파/아/썬 (6종) | `13 + (L−1)×3` | L30 → 100 |
| 팔라딘 홀리/디바인 (2종) | `43 + (L−1)×3` | L20 → 100 |
| 시그너스 소울/라이트닝 | `12 + (L−1)×2` | L20 → 50 |

| 차지 | 데미지 | 무반응 | 약점 | 반감 | 무효 |
|---|---|---|---|---|---|
| 플레임 L30 | 140% | 1.400 | 2.100 | 0.700 | 0 |

### 엘리멘탈 리셋 (플레임위자드) — 확정 ✅

`x = 스킬레벨 × 5%` (마스터20 = 100%). 공격 속성을 `r = x/100` 만큼 무속성화(§3-3 속성반응을 중립 쪽으로 blend):
```
유효 속성배율 = 몬스터반응배율 × (1 − r) + 1.0 × r
  master(r=1) → 항상 ×1.0 (완전 무속성: 무효·반감·약점 모두 무시)
  부분(r<1)  → 예) 무효(0)에 r=0.6 → ×0.6
```

### 중첩 규칙 — 확정 ✅

- **자기 데미지증가 버프**(콤보 / 버서크 / 엘앰프 / 차지)는 **직업 배타** → 캐릭터당 최대 1종.
- **위협**은 몬스터 디버프라 위 버프와 **곱연산 중첩** (`× 1.07`).
- 파이프라인 순서: 기본데미지 → 스킬% → **속성배율**(§3-3, 차지/리셋 반영) → 방어·렙차 → **자기 데미지증가 배율** → **위협 ×1.07** → 크리 기대배율 → clamp.

## 5. 위협 (팔라딘, 개편) — 확정 ✅

skill id **1201006**, master 20. (출처: ms-skill-simulator `120.json`)

상세: *"MP N 소비, 확률 prop%, time1초간 적 공격력 −pad%, **데미지 +damage%**, time2초간 명중률 −acc%"*

- **N방컷/DPM 관련 효과 = "몬스터가 받는 데미지 +damage%"** → 데미지 배율 `× (1 + damage/100)` (4장 배율과 동일 취급).
- 나머지(적 공격력 −pad%, 명중률 −acc%)는 **피격/생존 영역** → 이 섹션 계산엔 미반영(피격 섹션 대상).

**데미지 증가% (레벨별)**: 1~4:1, 5~8:2, 9~11:3, 12~14:4, 15~16:5, 17~18:6, 19~20:**7**

| 레벨 | 데미지 증가 | 적 공격력 | 명중률 | 확률 |
|---|---|---|---|---|
| 20(마스터) | +7% | −20% | −20% | 50% |

**관리 방식 = 파티버프** (샤프아이즈처럼). 몬스터 디버프라 어느 직업이든 곱연산 중첩. 켜져 있으면(**적용 기준**):
- **최종 데미지 ×(1 + damage/100)** = 마스터 **×1.07** → 이 섹션(N방컷/DPM) (신규 효과, §10)
- 적 공격력 −pad% · 명중 −acc% → **피격 섹션**이 동일 버프에서 읽어 반영 (피격 섹션에도 영향 주므로 파티버프 관리가 적합)
- 확률(50%)은 반영 안 함(적용 가정). 필요 시 옵션.

> 참고: 블로킹(1120005/1220006)도 개편(21레벨↑ 블록% 상향, 마스터 200 표기)됐으나 **방어 스킬**이라 본 섹션과 무관. 버프 데이터 재동기화는 별도 처리.

## 6. 크리티컬 (샤프아이즈)

- 소스: 버프 합산 `criticalP`(확률), `criticalDamage`(추뎀).
- **기대배율 근사**: 라인별 베르누이 전개 대신 범위 전체에 `f = 1 + criticalP × criticalDamage/100` 곱.
- N방컷·DPM 모두 동일 근사 사용.

## 7. N방컷 확률 (비보스)

1. 라인 최종 분포(3장) → 시전 분포(2.4~2.5, 난수 순환 반영해 합성) 구성.
2. 분포를 정수 데미지 bin으로 이산화(예: 폭 = max 데미지에 비례한 스텝).
3. N타 합 분포 = 시전 분포를 N회 **컨볼루션**.
4. 누적분포 `CDF(N) = P(N타 합 ≥ 몬스터 HP)`.
5. **정확히 N방** `= CDF(N) − CDF(N−1)`.

출력: N = 1..K (K=10 등) 각 방컷 확률 %. (모션 혼합 + min~max 변동이 확률로 반영됨)

- 성능: bin 수 × N × 라인 수 컨볼루션. bin ~수백, N ~10 → 충분히 가벼움.

## 8. DPM (보스)

```
DPM = 기대데미지_시전 × 분당_공격횟수
기대데미지_시전 = Σ 라인 기대데미지 (모션 확률가중 · 크리 기대 · 버프 반영)
분당_공격횟수 = 공속표(12장) 조회
```

- 보스 방어/렙차/속성 동일 적용.
- 참고값: 처치 소요시간 ≈ 보스HP / (DPM/60).

### 분당 공격횟수 결정 (공속표)

스킬은 3부류:
1. **공속 무관** — 고정 분당횟수 (예: 로어 30, 쉐도우웹 74).
2. **무기 공속 단계 의존** — 단계 **2(최고속)~9(최저속)**별 분당횟수.
3. **마법사** — 무기 공속 무관, **매직부스터** 유무만 영향(노말/부스터 2값). ※예외: 불독 **익스플로전**만 무기공속 영향(물리처럼 처리).

**무기 공속 = 개별 무기 아이템 속성** (무기타입 기본값이 아님!).
- 예: 두손검 대부분 6속이지만 일부 품목은 4·7속. → **카탈로그 `effects.attackSpeed`에 이미 저장됨(398/399)** ✅
- **최종 공속단계** = `무기.attackSpeed − 부스터 단계감소`, clamp[2,9].

**부스터 단계감소** — 스킬 데이터 `x` 필드에 이미 있음 ✅ (`x` = 공속 단계변화)
| 버프 | `x` (단계변화) | 예시 id |
|---|---|---|
| 일반 부스터(소드/엑스/메이스/스피어/폴암/보우/석궁/자벨린/대거/너클/건) | −2 (전 레벨) | 1101004, 3101002 … |
| 매직 부스터(스펠부스터) | Lv1~10 −1, **Lv11+ −2** | 2111005, 2211005 |
| 윈드 부스터(바이퍼·스트라이커) | Lv1~10 −1, **Lv11+ −2** | 5121009, 15111005 |

→ 부스터의 `x`를 읽어 자동 적용. 별도 매핑 불필요.

### 마법사 시전속도 · 윈드부스터

- 마법사 스킬(익스플로전 제외) = 노말/매직부스터 2값. **스펠부스터 Lv11+** 적용 시 매직부스터 값.
- **윈드부스터(파티버프, +2공속)** 는 메랜에서 마법사에도 적용되도록 변경됨. **단**:
  - 마법사에 윈드부스터 단독 적용 시 시전속도 = **미확인**.
  - **스펠부스터 + 윈드부스터 동시** 적용 시 = **데이터 없음**.
  - → 둘 다 **현재 미지원**(추정값 or 데이터 확보 시 구현). 안내 코멘트만.
- 윈드부스터는 파티버프로 **추가 예정**(바이퍼·스트라이커 사용, 물리 직업엔 −2단계 정상 적용).

> 실제 분당횟수 표는 12장 참조.

## 12. 공속표 (분당 공격횟수) — raw 기록

출처: 사용자 제공 표. **열 = 공속 단계**: 2(풀공속)·3(매우빠름)·4(빠름)·5(빠름)·6(보통)·7(느림)·8(느림)·9(매우느림). 값 = 분당 공격횟수.

### 12.0 해석 (프레임 기반 · 모션 공유)

- **30fps 프레임 기반**. 분당횟수 → 딜레이(ms)=60000/apm → 프레임=ms×30/1000.
  - 예) 쓰레셔 풀공속 100회 = 600ms = **정확히 18프레임**, 매우빠름 90회 = **20프레임**. 나머지 셀은 원본 정수프레임을 **반올림한 분당횟수**라 역산 시 소수가 나옴.
  - 프레임 증가폭이 단계 5·8에서 작아지는 3단계 주기 = 프레임 양자화 흔적.
- **대부분 스킬 = 평타 모션 기반** → 동일 곡선 공유. 고유 모션 스킬만 예외라 곡선이 다름(고정딜레이+스윙딜레이 비율 차이).
- 따라서 **단일 공식으로 대체하지 않고**, 데이터를 이렇게 구성:
  ```
  canonical '평타 곡선' = [100, 90, 83, 80, 74, 69, 67, 63]   // 공속 2~9

  ```
